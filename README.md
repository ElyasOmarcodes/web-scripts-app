# WebScripts — یو ځل لار وښایاست، تل به یې پخپله تعقیبوي

په ویب کې خپل کار یو ځل ترسره کړئ — پروګرام ټول کلیکونه، لیکل او تنظیمات **ثبتوي**.
بیا چې کله وغواړئ، په یوه تڼۍ ټوله لار **پخپله** بیا ترسره کوي.

| | |
|---|---|
| پلټفورم | Windows 10/11 |
| بېک اېنډ | Python 3.10+ |
| ظاهري ډیزاین | Flutter 3.27+ (Dart) — د macOS په څېر · **وزیرمتن** فونټ |
| اتومات کول | Selenium + Edge / Chrome / Brave / Vivaldi / Opera |
| اکاونټونه | یو ځل ننوتل — کوکیز خوندي کېږي، بیا پټنوم نه غواړي |
| پروکسي | هر اکاونټ خپله پته — HTTP/SOCKS، له پټنوم سره |
| پېژندګلوي | هر اکاونټ خپله وسیله — ۱۰۰ بشپړ browser/device چاپېریالونه |
| امنیت | د پروګرام خپل پټنوم · د ویندوز پټنوم · د ګوتې نښه (اختیاري) |
| بسته | یو واحد `WebScripts-Setup.exe` + پورټبل `.7z` (GitHub Actions یې جوړوي) |

## کارونه — سکریپټ + اکاونټونه

سکریپټ وایي **څه وکړه**؛ کار وایي **د چا په نامه یې وکړه**. که د ایکس درې
اکاونټونه لرئ، دا یو کار دی چې درې واړه پکې دي — او پروګرام یادوي چې هر یو یې
څنګه تېر شو.

> سکریپټونه نور په خپله پاڼه کې نه چلېږي. هلته یې یوازې ثبتوئ او سموئ؛ چلول
> د **کارونو** له لارې کېږي.

### د کار تنظیمات

| | |
|---|---|
| **نوم** | چې په لیست کې یې وپېژنئ |
| **سکریپټ** | کوم ثبت شوی سکریپټ دې وچلېږي |
| **اکاونټونه** | د هرې کټګورۍ خپل ټب، او د هغه ټب دننه د لټون کړکۍ |
| **بصري یا پټ** | براوزر ښکاري، یا بک ګراونډ کې چلېږي (لاندې وګورئ) |
| **همزمانه کړکۍ** | څومره چې وغواړئ — پروګرام درته وایي چې دا شمېر ستاسو پر کمپیوټر څومره فشار دی |
| **د اکاونټونو ترمنځ ځنډ** | چې ټول یو ځل ونه لیدل شي |
| **په لومړۍ تېروتنه ودرېږه** | یا پاتې اکاونټونه هم وچلوه |
| **براوزر پرانیستی پرېږده** | د کار له پای ته رسېدو وروسته |

### د کارونو لیست

هر کار خپل رنګ لري:

| رنګ | معنا |
|---|---|
| 🟢 شین | ټول اکاونټونه بشپړ شول |
| 🔴 سور | ټول ناکام شول |
| 🟡 ژیړ | نیمایي کې پاتې — ځینې بشپړ، ځینې لا نه دي چلېدلي |
| ⚪ سپین | لا یو ځل هم نه دی چلېدلی |

د پاڼې پورته برخه کې د **فلټر** ټکي (ټول · روان · بشپړ · نیمګړي · ناکام، هر یو
خپل شمېر سره) او د **لټون** کړکۍ ده.

هر کار یوه اصلي تڼۍ لري (**چلول** یا **دوام ورکړه**) او یو **⋯ منو** چې دا
پکې دي: **لاګ وګوره** · **له سره وچلوه** · **تنظیمات** · **ړنګول**.

### د هر کار خپل لاګ

هر کار خپل لاګ فایل لري (`task-logs/<id>.jsonl`) — نو هغه کار چې تېره اونۍ
چلېدلی و، لا هم لوستلی شئ: کوم اکاونټ بریالی شو، کوم ناکام او ولې، او د
چلولو پر مهال یې څومره پروسیسر او حافظه ونیوله.

### څو کړکۍ زما کمپیوټر زغمي؟

کله چې شمېره بدلوئ، پروګرام سمدلاسه حساب کوي:

```
۴ کړکۍ ≈ ۲٫۵ هستې له ۸ · ~۱٫۷GB حافظه   [اسانه]
ستاسو کمپیوټر تر ۹ کړکیو پورې اسانه چلوي.
```

دا اټکل د کمپیوټر له ریښتینو هستو او ازادې حافظې څخه جوړېږي (`psutil`)، او د
یوې کروم کړکۍ اوسط لګښت پرې ضرب کېږي. **پټ (headless)** حالت کې پروسیسر نږدې
**۳۵٪** او حافظه نږدې **۲۰٪** کمه کارېږي — ځکه چې پاڼه نه انځورېږي او کړکۍ نه
جوړېږي. خو یاد ولرئ: ځینې سایټونه پټ براوزر اسانه پېژني، نو د قیمتي اکاونټ
لپاره بصري حالت خوندي دی.

د چلولو له پای ته رسېدو وروسته، ریښتینې اندازه هم په لاګ کې لیکل کېږي، نو
اټکل او واقعیت پرتله کولی شئ.

**دوام ورکړه** هغه ستونزه حل کوي چې تاسو یې یادونه وکړه: که مو درې ایکس
اکاونټونه وو او په دویم کې ودرېد (قصداً یا په تېروتنه)، «دوام ورکړه» یوازې
هغه اکاونټونه چلوي چې پاتې دي — لومړی له سره نه پیلېږي. د هر اکاونټ حالت د
کار د کارټ لاندې د یوې کوچنۍ نښې په بڼه ښکاري (`4/6` یعنې څلور ګامه له شپږو).

## ستاسو مثال: د فیسبوک ټم بدلول

1. برنامه پرانیزئ او **«نوې لارښوونه»** ووهئ
   نوم: `د فیسبوک ټم` — پته: `https://www.facebook.com`
2. Edge پرانیستل کېږي، پورته ښي خوا کې سور نښان ښیي چې **ثبتول روان دي**
3. په براوزر کې خپله لار تعقیب کړئ:
   مینو ← تنظیمات ← ښکارېدنه ← تیاره ټم
4. بېرته برنامې ته راشئ او **«ثبتول ودروه»** ووهئ
5. سکریپټ خوندي شو ✔

له دې وروسته یوازې د **▶ چلول** تڼۍ کافي ده — پروګرام به پخپله همغه لار ووهي.

> **مهمه:** برنامه د Edge لپاره یو ځانګړی پروفایل کاروي، نو یو ځل چې فیسبوک ته
> ننوځئ، هره بله ګرځېدنه کې هم ننوتلی یاست — د بیا بیا پټنوم لیکلو اړتیا نشته.

## اکاونټونه — یو ځل ننوځئ، بس

ستاسو ستونزه دا وه: هر ځل چې د فیسبوک ټم بدلولو سکریپټ چلېږي، بیا ننوتل پکار
وي. د **اکاونټونو** پاڼه دا حل کوي.

1. **«نوی اکاونټ زیاتول»** ووهئ → د سایټ لیست ښکاري (فیسبوک، ایکس، انسټاګرام،
   ګوګل، لینکډان، یوټیوب، ټیک ټاک، ټلګرام، بل سایټ)
2. یو یې وټاکئ → د هغه د **ننوتلو پاڼه په یوه کوچنۍ کړکۍ کې** پرانیستل کېږي
3. تاسو هلته په عادي ډول ننوځئ. پروګرام پخپله پېژني چې ننوتل بشپړ شول (د سایټ
   د ناستې کوکي په لیدو) او **کوکیز خوندي کوي** — یا په لاسي ډول «ننوتم» ووهئ
4. اکاونټ خپلې کټګورۍ ته اضافه کېږي

له دې وروسته چې کله یو سکریپټ وچلوئ، پروګرام پوښتي **«د کوم اکاونټ په نامه
یې وچلوم؟»** — هغه اکاونټ چې وټاکئ، د هغه کوکیز او پروفایل کارېږي.

**د ثبتولو پر مهال هم همداسې:** د «نوې لارښوونه» په کړکۍ کې د **اکاونټ** کرښه
ده. که هلته یو اکاونټ وټاکئ، براوزر له همغه اکاونټ سره پرانیستل کېږي او سایټ
به بیا د ننوتلو پاڼه ونه ښیي.

### حد اکثر اکاونټونه

هره کټګوري خپل حد لري او د پاڼې په پای کې یې بدلولی شئ:

| سایټ | لومړنی حد |
|---|---|
| فیسبوک | ۲ |
| ایکس (ټویټر) | ۳ |
| انسټاګرام | ۱ |
| ګوګل / یوټیوب | ۲ |
| لینکډان / ټیک ټاک / ټلګرام | ۱ |

### د کوکیزو ژوندی/مړ حالت

د اکاونټونو پاڼه کې هر اکاونټ یوه کوچنۍ رڼا لري:

| رنګ | معنا |
|---|---|
| 🟢 شین | کوکیز ژوندي دي — سایټ ناسته وپېژندله |
| 🔴 سور | مړه دي — بیا ننوتل پکار دي |
| 🟡 ژیړ | همدا اوس کتل کېږي |
| ⚪ خړ | لا نه دي کتل شوي (یا انټرنیټ نه و) |

**«کوکیز وګوره»** تڼۍ هر اکاونټ ته د هغه خپل سایټ پوښتي: کوکیز په یوه پټه
کړکۍ کې پلي کېږي او لیدل کېږي چې سایټ لا هم ناسته پېژني که نه. که کتنه ونه
شي (انټرنیټ نشته، براوزر نه پرانیستل کېږي) حالت **خړ** پاتې کېږي — هېڅکله
سور نه شي، ځکه غلط سور به مو بې ځایه بیا ننوتلو ته اړ کړي.

همدا رڼا د **کار د تنظیماتو** په اکاونټ لیست کې هم ښکاري، نو مړ اکاونټ به مو
په کار کې ونه غورځول شي. د پاڼې پورته برخه کې د **فلټر** (ټول · ژوندي · مړه ·
نامعلوم) او **لټون** افشنونه دي.

### څنګه خوندي دي؟

- **پټنوم هېڅکله نه ذخیره کېږي** — تاسو یې یوازې په براوزر کې لیکئ
- هر اکاونټ خپل **جلا د براوزر پروفایل** لري، نو ناستې سره نه ګډېږي
- کوکیز په `%LOCALAPPDATA%\WebScripts\accounts\cookies\` کې دي، یوازې د
  مالک د لوستلو اجازې سره (`0600`) — او هېڅکله له کمپیوټره نه وځي

> د ناستې کوکیز د پټنوم هومره حساس دي: څوک چې یې ولري، ننوتلی دی. که کمپیوټر
> بل چا سره شریکوئ، اکاونټونه له همدې پاڼې ړنګ کړئ.

## براوزر

پروګرام پخپله ګوري چې ستاسو کمپیوټر کې کوم براوزر **په ریښتیا نصب دی** —
Edge، Chrome، Brave، Chromium، Vivaldi، Opera. په تنظیماتو کې یې لیست ګورئ
(نسخه + لاره) او هر یو ټاکلی شئ. «اتوماتیک» لومړی Edge غوره کوي.

Firefox پېژندل کېږي خو لا ملاتړ نه کېږي (Chromium پکار دی).

## نصبول

```powershell
git clone <repo-url>
cd web-scripts-app
powershell -ExecutionPolicy Bypass -File scripts\setup.ps1
```

setup سکریپټ دا کارونه کوي:

- د Python مجازي چاپېریال (`backend\.venv`) جوړوي او کڅوړې نصبوي
- د Flutter وینډوز برخه جوړوي (`flutter create --platforms=windows`)
- ګوري چې Edge نصب دی که نه

**د Edge ډرایور نصبولو ته اړتیا نشته** — Selenium یې پخپله راکوزوي.

## چلول

```powershell
powershell -ExecutionPolicy Bypass -File scripts\run.ps1
```

که Flutter نه لرئ، یوازې بېک اېنډ هم بشپړ کار کوي:

```powershell
powershell -ExecutionPolicy Bypass -File scripts\run.ps1 -BackendOnly
```

## یو واحد exe جوړول

هر ځل چې کوډ پورته شي، GitHub Actions پخپله وینډوز نسخه جوړوي:
`.github/workflows/build-windows.yml`

- backend د **PyInstaller** په مرسته یو `webscripts-backend.exe` ته بدلېږي (Python ته اړتیا نشته)
- Flutter وینډوز نسخه جوړېږي
- دواړه د **Inno Setup** په مرسته یو واحد **`WebScripts-Setup-0.1.0-x64.exe`** ته بدلېږي
- پورټبل نسخه د **LZMA2** (همغه د xz کمپرسر) په مرسته فشرده کېږي:
  `WebScripts-Portable-0.1.0-x64.7z`

> xz پخپله یوازې **یو فایل** فشرده کولی شي — له همدې امله `tar.xz` شته: لومړی
> tar ټول فایلونه یو کوي، بیا یې xz فشرده کوي. `.7z` همغه LZMA2 کاروي خو پخپله
> ټوله پوښه اداره کوي، نو نه tar پکې شته او (solid) حجم یې لا کم دی — په دې
> پروژه کې د tar.xz په پرتله ۷٪ کوچنی.

هر ورک فلو **یو ریلیز** جوړوي (`build-<شمېره>`) چې دواړه فایلونه پکې دي، او
مخکینی ریلیز پخپله ړنګېږي — نو تل یوازې وروستۍ نسخه پاتې کېږي.
د Actions **Artifact** کې یوازې پورټبل `.tar.xz` اچول کېږي، ترڅو حجم یې لوړ نشي.

پورټبل نسخه د **7-Zip** یا **WinRAR** په ښي کلیک سره پرانیستل کېږي.

په خپل کمپیوټر کې همدا کار:

```powershell
powershell -ExecutionPolicy Bypass -File packaging\build_windows.ps1
```

## څه ثبتېږي او چلول یې څومره ژر دي؟

> **د هر سکریپټ خپله فاصله:** د سکریپټ پاڼې کې د **تنظیماتو** تڼۍ ده — هلته
> ټاکلی شئ چې د دې سکریپټ د دوو کړنو تر منځ فاصله له څو تر څو **ملي ثانیو**
> تصادفي وي. که ونه ټاکئ، عمومي تنظیمات کارېږي.


سکریپټ **یوازې ستاسو تعاملات** ساتي — کلیک، دوه ځله کلیک، ښي کلیک، لیکل،
لیست ټاکل، تڼۍ (Enter، Esc، غشي، Ctrl+A …)، سکرول، نوې کړکۍ، پاڼې.

هغه څه چې **نه** ثبتېږي: هغه دمه چې تاسو یې د دوو کارونو ترمنځ فکر کولو ته
کاروئ. پخوا به دا هم ثبتېده، نو هر ځل چلول به د ثبتولو د ورځې تر ټولو ورو
شېبې هومره ورو و. اوس چلول خپل تال لري:

- د ګامونو تر منځ **تصادفي ۰٫۵–۱٫۵ ثانیې** (د اکاونټ ساتنې لپاره، لاندې وګورئ)
- عنصر ته انتظار یوازې تر هغې چې پیدا شي
- هغه ګام چې کېدای شي بیا رانغلی وي (لکه د کوکیزو پیغام) یوازې **۲٫۵ ثانیې**
  انتظار کوي، بیا پرېښودل کېږي — نه ټول ۱۵ ثانیې

## پروکسي — چې ټول اکاونټونه له یوې پتې ونه ښکاري

که ستاسو درې د ایکس اکاونټونه ټول له یوه ای‌پي څخه وصل شي، سایټ ته دا یو کس
دی چې درې اکاونټونه لري — او دا هغه څه دي چې د بندېدو لامل ګرځي. د **پروکسي**
پاڼه همدا حل کوي.

### زیاتول

د خرڅوونکي (لکه Webshare) لیست مو دلته یو ځای **پېسټ** کړئ. دا بڼې پېژندل کېږي:

```
host:port
host:port:user:pass          ← تر ټولو عام
user:pass@host:port
http(s)://user:pass@host:port
socks5://host:port
```

هغه کرښې چې ونه پېژندل شي، درته لیست کېږي — او هغه چې مخکې شته وي، بیا نه
زیاتېږي. **د پروکسۍ پټنومونه ستاسو په کمپیوټر کې پاتې کېږي** (`proxies.json`،
یوازې د مالک د لوستلو اجازه) او هېڅکله بهر نه لېږل کېږي.

### کتنه

**«ټولې وګوره»** هرې پروکسۍ ته یو ریښتینی غوښتنه لېږي او دا درته راوړي:

| | |
|---|---|
| 🟢 ژوندۍ | ځواب یې ورکړ |
| 🔴 مړه | ځواب نشته، یا کارن‌نوم/پټنوم یې ونه منل (407) |
| ⚪ نامعلومه | لا نه ده کتل شوې (یا SOCKS ده چې له دې ځایه نه شي کتل کېدای) |

او همدارنګه: **وتنځی ای‌پي** (هغه پته چې سایټ یې ویني، نه د پروکسۍ خپله)،
**ځای** (هېواد · ښار) او **د ځواب وخت** په ملي ثانیو.

### اکاونټ ته پروکسي ورکول

دوه لارې دي:

1. **«اکاونټونو ته ووېشه»** — یو کلیک، هر اکاونټ ته یوه جلا پروکسي، ګډوډ شوې.
   که پروکسۍ له اکاونټونو کمې وي، درته وایي چې څو یې شریکوي.
2. **د هر اکاونټ له کارټ څخه** — د پروکسۍ کرښه کلیک کړئ او یې وټاکئ.

هر اکاونټ درې حالته لري:

| | |
|---|---|
| **بې پروکسي** | د کمپیوټر له خپلې پتې |
| **ټاکلې پروکسي** | تل له همدې یوې پتې — **سپارښتنه همدا ده** |
| **هر ځل تصادفي** | هر چلولو کې بله پروکسي |

> **ولې ټاکلې غوره ده؟** هغه اکاونټ چې ای‌پي یې هره ورځ بدلېږي، سایټ ته ډېر
> عجیب ښکاري له هغه چې تل له یوې پتې راځي. تصادفي حالت شته، خو د قیمتي
> اکاونټ لپاره یې نه وړاندیز کوم.

پروکسي په **هر** ځای کې کارېږي: د کار چلول، سکریپټ ثبتول، لومړی ځل ننوتل، او
حتی د کوکیزو کتنه — که کوکیز له بلې پتې وکتل شي، سایټ ته بیا هم عجیب ښکاري.

> **یادونه:** هغه پروکسي چې پټنوم غواړي، کروم د کمانډ لاین له لارې نه مني — نو
> پروګرام یوه کوچنۍ اضافه (extension) جوړوي چې براوزر ته پروکسي ورپېژني او د
> پټنوم پوښتنه ځواب کړي. د براوزر په تړلو سره هغه فایل هم ړنګېږي.

## د اکاونټ ساتنه (بلاک کېدو مخنیوی)

دا برنامه ستاسو د خپلو اکاونټونو مرستیاله ده، نو د چلولو چلند یې قصداً د
ماشین په څېر **نه** دی. په تنظیماتو کې د «د اکاونټ ساتنه» برخه دا کنټرولوي:

- **د کلیکونو تر منځ ۰٫۵–۱٫۵ ثانیې تصادفي فاصله** (که ثبتولو کې مو ډېر ځنډ
  کړی وي، هغه ساتل کېږي — تل د دواړو لویه)
- **د ویجټ دننه تصادفي ټکی کلیک کېږي**، نه یې دقیق مرکز
- **کله ناکله لږ سکرول** — لکه یو کس چې پاڼه لولي
- **حرف په حرف لیکل** د تصادفي وقفو سره، نه یو ځل ټول متن
- براوزر ته ویل کېږي چې **ځان د اتومات وسیلې په توګه ونه پېژني**
  (`navigator.webdriver` او نور نښې پاکېږي)
- هر اکاونټ **خپل پروفایل** لري، نو ناستې سره نه ګډېږي

### د براوزر پېژندګلوي — هر اکاونټ خپله وسیله

پروکسي دا پټوي چې **له کومې پتې** راځئ. خو سایټ یوازې پته نه ګوري: هر ځل
براوزر یو کوچنی «د ګوتو نښان» هم ورکوي — د براوزر نوم او نسخه، د عاملې
سیستم، د سکرین اندازه، د CPU هستې، حافظه، د ګرافیک کارت نوم، ساعت او ژبه.
که پنځه اکاونټه له پنځو مختلفو پتو راشي خو **ټول یو شان براوزر** ولري، سایټ
بیا هم پوهېږي چې یو کس دی.

نو هر اکاونټ ته د جوړېدو پر مهال **یوه بشپړه وسیله** ورکول کېږي — او **تل
همدا یوه** پاتې کېږي.

> **یوازې یوزر اجنټ بدلول کافي نه دي — بلکې زیانمن دي.** که یوزر اجنټ ووایي
> «آیفون» خو نور دولس نښې ووایي «ویندوز ډیسکټاپ، بې لمس، NVIDIA ګرافیک»،
> سایټ دا نه زده کوي چې آیفون یو — بلکې دا زده کوي چې **درواغ وایو**. دا له
> دوو اکاونټونو سره د یو عادي یوزر اجنټ شریکولو څخه ډېر قوي نښه ده.

نو دلته د **ټولې وسیلې** جوړول کېږي، نه یوازې د یوزر اجنټ:

| څه بدلېږي | څنګه |
|---|---|
| یوزر اجنټ | د کمانډ لاین + CDP دواړو له لارې |
| `Sec-CH-UA` کلاینټ هینټونه | له یوزر اجنټ سره سم برانډ/نسخه/پلټفورم |
| `Accept-Language` او ژبې | **د پروکسي هېواد** ټاکي یې |
| ساعتمهال (timezone) | **د پروکسي ښار/هېواد** ټاکي یې |
| د سکرین اندازه، DPR | د وسیلې خپله اندازه — کړکۍ یې هېڅکله نه ماتوي |
| CPU هستې، حافظه، لمس | د وسیلې خپل ارقام |
| د ګرافیک کارت (WebGL) | د وسیلې خپل نوم |
| Canvas / Audio شور | **د اکاونټ خپل تخم** — دوه اکاونټه په یوه وسیله هم یو شان نه دي |

**د خطر درې کچې:** د اکاونټونو په پاڼه کې چې پېژندګلوي بدلوئ، درې ډلې ګورئ:

| ډله | څه دي | کارول |
|---|---|---|
| **ډېر خوندي** (۲۱) | ویندوز ډیسکټاپ کروم/اېج | اتومات همدا ورکول کېږي |
| **منځنی** (۲۷) | مک / لینکس / کروم‌بوک | په لاس ټاکل کېږي |
| **پاملرنه غواړي** (۵۲) | تلیفونونه او ټابلیټونه | **هېڅکله اتومات نه ورکول کېږي** |

اتومات ټاکل څلور قاعدې لري:

1. **هېڅکله تلیفون نه ورکوي** — ډیسکټاپ براوزر چې ځان تلیفون ښیي، لومړۍ پاڼه
   یې د کړکۍ له اندازې څخه ونیسي.
2. **هېڅکله تر حقیقي براوزر نوې نسخه نه ښیي.** دا د نیول کېدو خبره نه ده —
   د **ماتېدو** خبره ده. سایټ چې باور وکړي له کروم ۱۴۵ سره خبرې کوي، هماغه
   جاواسکریپټ لېږي چې ۱۴۵ یې پوهېږي؛ که ستاسو براوزر ۱۳۸ وي، هغه کوډ پرې
   نه چلېږي او **یوه تڼۍ بې غږه کار پرېږدي**. زړه نسخه ښودل بې خطره ده —
   سایټ زوړ کوډ لېږي، او نوی انجن یې په اسانۍ چلوي.
3. **د حقیقي براوزر نږدې نسخه** — «۱۰۸ یم» ویل هم سم نه دي؛ یوه کرښه
   جاواسکریپټ یې ثابتوي.
4. **وېش** — له پاتې نه هغه اخلي چې **تر ټولو لږ کارول شوې** ده.

که پخوانۍ پېژندګلوي له حقیقي براوزر څخه نوې وي، د اکاونټونو په پاڼه کې سور
خبرداری راځي او **«سم یې کړه»** تڼۍ یې په یوه کلیک سموي.

### که کوم سایټ بد چلند وکړي

د پېژندګلوۍ په پاڼه کې تر ټولو پورته یوه بټنه ده: **«پېژندګلوي بنده کړه»**.
براوزر بیا ځان همغسې ښیي لکه څنګه چې دی. که ستونزه ورکه شوه، لامل یې
پېژندګلوي وه؛ که پاتې شوه، لامل یې بل څه دی — او دا په یوه کلیک معلومېږي.

او د ننوتلو په کړکۍ کې، پروګرام اوس **د سایټ خپلې تېروتنې** هم لولي او
ښیي — نو که یوه تڼۍ کار ونه کړي، دلیل یې په لاګ کې لیکل کېږي، نه چې اټکل
وکړو.

که دوه اکاونټه یوه وسیله ګډه کړي، د اکاونټونو پاڼه پخپله **ژیړه خبرداری**
راباسي.

### نور خوندیتوب چې اضافه شو

- **WebRTC بند** — پروکسي TCP وړي؛ WebRTC خپله UDP لار پرانیزي او هلته
  **حقیقي پته** ښکاري. دا تر ټولو لوی سوری دی چې پروکسي یې نه تړي — اوس د
  براوزر په کچه او په صفحه کې دواړه بند دی.
- **ځای (geolocation) رد کېږي** — ځواب یې د GPS/WiFi له مخې وي، نه د پروکسي،
  نو حقیقي ښار به یې ورکړ.
- **د اکاونټ کړکۍ اندازه ثابته ده** — «maximized» د حقیقي مانیټور اندازه
  ورکوي، چې پر ټولو اکاونټونو یو شان ده.
- **لومړی ننوتل هم له همدې پروکسي او همدې وسیلې کېږي** — اکاونټ چې له یو ځای
  جوړ شي او له بل ځای وکارول شي، تر ټولو زوړ سور بیرغ دی.
- **د یوې پتې خبرداری** — که دوه اکاونټه د یوه سایټ له یوې پروکسي ووځي،
  پاڼه یې وايي او د حل تڼۍ ورسره ده.

## پټنوم — د پروګرام خپله کولپ

لومړی ځل چې پروګرام خلاص کړئ، بله هېڅ پاڼه نه ښکاري تر څو **خپل پټنوم** ونه
ټاکئ. له هغې وروسته هر ځل چې پروګرام خلاص شي، همدا پټنوم غواړي.

> دا پټنوم د **کمپیوټر** له پټنوم څخه جلا دی او په اتومات ډول ورسره یو نه
> کېږي — دوه جلا رازونه له یوه راز څخه غوره دي. که وغواړئ چې د کمپیوټر
> پټنوم هم کار وکړي، یو ټیک شته.

### څه شی او ولې کلپ کېږي

پروګرام داسې څه ساتي چې د غلا وړ دي: د اکاونټونو **کوکیز** (چې پخپله د
ننوتلو کیلي ده)، د **پروکسیو پټنومونه**، او د اکاونټونو **خپل کارن‌نومونه او
پټنومونه**. نو یوه کولپ ورته اېښودل شوې.

| څنګه کار کوي | |
|---|---|
| کیلي | یو تصادفي ۳۲-بایټه کیلي، یوازې یو ځل جوړېږي او هېڅکله له دې کمپیوټره نه وځي |
| د کیلي ساتنه | همدا کیلي د هرې لارې لاندې جلا کلپ کېږي (scrypt + AES-GCM) |
| پټنوم پخپله | **هېڅ ځای کې نه لیکل کېږي** — نه په فایل، نه هش، هېڅ نه |
| فایل | `security.json`، یوازې ستاسو د کارن‌نوم لپاره لوستل کېدونکی (0600) |
| غلط پټنوم | تر پنځو هڅو وروسته هره هڅه ورو کېږي |

### درې لارې، یوه کیلي

| لار | څنګه | یادونه |
|---|---|---|
| **د پروګرام پټنوم** | تل شته | دا هغه لار ده چې تل بېرته پرې راتلی شئ |
| **د کمپیوټر پټنوم** | ویندوز پخپله یې کوي (`LogonUser`) — موږ یې نه ساتو | اختیاري |
| **د ګوتې نښه** | ویندوز هیلو | اختیاري |

> **ولې د پروګرام پټنوم پاتې کېږي؟** که یوازې د ویندوز پټنوم وای او تاسو یې
> په ویندوز کې بدل کړئ، بیا نو **تل** له خپلو اکاونټونو بهر پاتې کېدلئ. نو
> نورې لارې **زیاتېږي**، لومړۍ نه بدلوي.

### د ګوتې نښه — درې حالتونه

| حالت | څه ښکاري |
|---|---|
| لوستونکی شته + ګوته ثبت ده | ټیک فعال دی |
| لوستونکی شته، ګوته نه ده ثبت | ټیک بند، خو یوه تڼۍ: **«ګوته ثبت کړه»** → د ویندوز پاڼه پرانیزي |
| لوستونکی نشته | ټیک **ډیسیبل** دی، او لاندې یې لامل لیکلی وي |

ګوته ثبتول د عاملې سیستم کار دی — هېڅ پروګرام ته یې اجازه نشته — نو تر ټولو
رښتیني چې یو پروګرام یې کولی شي، دا ده چې تاسو هماغه پاڼې ته بوځي.

## د اکاونټ خپله پاڼه

د اکاونټونو په ګریډ کې یو کارډ کلیک کړئ — د هغه اکاونټ بشپړه پاڼه پرانیزي:
د کوکیزو حالت، له کومې پتې وځي، کومه وسیله ښکاري، او دوه کلپ شوې برخې:

### کوکیز — ډیفالټ پټ

د کوکیزو **نومونه** او ډومینونه تل ښکاري. خو **ارزښتونه** پټ دي. د سترګې پر
تڼۍ چې کلیک وکړئ، پروګرام **پټنوم غواړي** — او یوازې تر هغه وروسته یې ښیي.

> ولې؟ ځکه کوکي پخپله ننوتل دي. څوک چې د `xs` کوکي ولري، له پټنوم پرته
> ستاسو فیسبوک ته ننوتلی شي. سهار پروګرام پرانیستل، د ماسپښین د کوکي د
> ښودلو اجازه نه ده.

### کارن‌نوم او پټنوم — محلي، کلپ شوي

د هر اکاونټ خپل کارن‌نوم او پټنوم هم همدلته ثبتولی شئ. پروګرام یې پخپله نه
کاروي (ننوتل لا هم په کوکیزو کېږي) — دا هغې ورځې لپاره دي چې کوکیز مړه شي.

فایل کې یې **ساده متن نشته**: هر اکاونټ د پروګرام د کیلي لاندې کلپ شوی دی، او
لیدل یې بیا **پټنوم غواړي**. لیست کې یوازې دومره ښکاري چې «څه ثبت دي» — نه دا
چې څه.

## وړل او راوړل (CSV، JSON، Python، JavaScript)

درې پاڼې یې لري، او **هره یوه یې پټنوم غواړي**:

| چېرته | څه وځي | څه راځي |
|---|---|---|
| **اکاونټونه** — د پاڼې په سر کې «وړل / راوړل» | CSV: نوم، کټګوري، د کوکیزو حالت، پروکسي، پېژندګلوي — او په خوښه **کوکیز** | CSV |
| **پروکسي** — د پاڼې په سر کې | CSV: پته، پورټ، حالت، وتنځی IP، ځای | CSV یا هماغه ساده لیست چې خرڅوونکي درکړی |
| **سکریپټونه** — د پاڼې په سر کې | JSON · **Python (Selenium)** · **JavaScript (Playwright)** · CSV لنډیز | JSON |

په دریو واړو پاڼو کې تڼۍ په یوه ځای کې ده — د نورو تڼیو ترڅنګ، د پاڼې په سر کې.

**پټنومونه پکې نه وځي** — نه د اکاونټونو، نه د پروکسیو — تر څو یې په خپله
ژبه ونه غواړئ. هغه ټیک ژیړ خبرداری ورسره لري، ځکه فایل یو داسې کاپي ده چې
بیا یې څوک نه ساتي.

### کوکیز هم ورسره (د اکاونټونو لپاره)

د اکاونټونو په وېستلو کې یو دویم ټیک شته: **«کوکیز هم ورسره وساته»**. که یې
ووهئ، د هر اکاونټ ناسته هم په CSV کې ځي — نو بل کمپیوټر ته یې چې راوړئ،
اکاونټ **ننوتی** راځي او بیا ننوتل نه غواړي.

> همدا ځکه یې خبرداری ژیړ دی: هغه کالم پخپله ننوتل دي. څوک چې فایل ولري،
> ستاسو اکاونټ ته ننوتلی شي — له پټنوم پرته. یوازې هغه وخت یې وکاروئ چې فایل
> خوندي ځای ته وړئ.

که فایل کوکیز ونه لري، راوړل شوي اکاونټونه یو ځل ننوتل غواړي — او پروګرام
پخپله وايي چې څو یې له ناستې سره راغلل.

### CSV او پښتو

فایل د BOM سره لیکل کېږي، نو اېکسل پښتو سم ښیي — نه ناڅرګند سمبولونه. د
کالمونو نومونه انګلیسي دي تر څو فایل سم بېرته راوړل شي. د راوړلو پر مهال
کاما او سیمي‌کولن دواړه پېژندل کېږي (اروپایي اېکسل سیمي‌کولن لیکي).

### سکریپټ → کوډ

`py` او `js` بڼې **د چلولو وړ کوډ** دی، نه یوازې یو لیست:

* د هر عنصر **ټولې نښې** ورسره وځي (لکه پخپله پروګرام کې)، نو یوه کوچنۍ د
  سایټ بدلون یې نه ماتوي؛
* د ګامونو ترمنځ **هماغه تصادفي فاصله** پکې ده؛
* د پټنوم ګامونه د `VARIABLES` په بڼه وځي — **پټنوم پخپله نه وځي**؛
* iframe ته ننوتل، `select`، تڼۍ، سکرول — ټول ژباړل شوي دي.

فایلونه دلته ولیکل کېږي: `%LOCALAPPDATA%\WebScripts\exports`

## کله ناسته ژر مړه شي — د پروکسي ډول

که د پروکسي سره ننوځئ، فیسبوک ښه راشي، بیا **۳۰–۴۰ ثانیې وروسته** بیرته
لاګین پاڼه راشي او کوکیز مړه شي — دا د پروګرام ستونزه نه ده او د انټرنیټ هم
نه. دا د **پتې ډول** دی.

| د پتې ډول | سایټ یې څنګه ګوري |
|---|---|
| **موبایل** (د ګرځنده شبکې) | تر ټولو ښه — واقعي خلک همدلته دي |
| **د کور لاین** (residential) | ښه — د باور وړ |
| **ډېټاسنټر** (سرور فارم) | بد — هلته څوک نه اوسېږي؛ فیسبوک/انسټاګرام یې ناستې غورځوي |
| **پېژندل شوې پروکسي/VPN** | تر ټولو بد — لا دمخه په لیستونو کې ده |

**وړیا او ارزانې پروکسي تقریباً تل ډېټاسنټر دي** — او زرګونه کسان یې پر همدې
سایټونو کارولې، نو سایټ یې لا دمخه پېژني. اړیکه یې سمه نیول کېږي (پاڼه
پرانیزي)، خو ناسته ژر غورځول کېږي.

اوس د پروکسي پاڼه دا پخپله ښیي: تر «وګوره» وروسته هرې پروکسي ته یو نښان
ورکول کېږي — **ډېټاسنټر** (سور)، **د کور لاین** (شین)، **موبایل** (شین)،
**پېژندل شوې** (سور) — او که کومه سوره وي، پورته یې خبرداری راځي.

> **سپارښتنه:** د قیمتي اکاونټونو لپاره یا **residential/mobile** پروکسي
> واخلئ، یا هېڅ پروکسي مه کاروئ. یوه بده پروکسي تر «بې پروکسي» ډېره خطرناکه
> ده.

### او دا هم: پته مه بدلوئ

اکاونټ چې له یوې پتې ننوځي او بیا له بلې وکارول شي، ډېری سایټونه ناسته
غورځوي — همدا هغه څه دي چې «فیسبوک راغی، بیا بیرته لاګین وغوښت».

نو پروګرام اوس هغه پته **ثبتوي** چې ناسته ترې زېږېدلې، او که راتلونکی چلولو
کې پته بدله وي، **مخکې له چلولو** وايي:

> «دا اکاونټ له ‹د کمپیوټر خپله پته› څخه ننوتی و، خو اوس له ‹Germany ·
> Frankfurt› ځي… یا پخوانۍ پته بیرته وټاکئ، یا له همدې نوې پتې یو ځل بیا
> ننوځئ.»

## کله چې براوزر وايي «انټرنیټ نشته»

که د پروګرام دننه سکریپټ چلوئ او براوزر وايي پاڼه نه پرانیزي، خو **هماغه
لینک په عادي براوزر کې ښه پرانیزي** — تقریباً هېڅکله انټرنیټ نه وي. دا دي
حقیقي لاملونه، په ترتیب:

| څه ښکاري | حقیقي لامل |
|---|---|
| `ERR_PROXY_CONNECTION_FAILED` | پروکسي مړه ده، یا **ستاسو IP د پروکسي په اجازه‌لیست کې نشته** |
| `ERR_TUNNEL_CONNECTION_FAILED` | کارن‌نوم/پټنوم ونه منل شو، یا همدا اجازه‌لیست |
| `ERR_TIMED_OUT` (پروکسي ټاکلې وي) | پروکسي ځواب نه ورکوي |
| `ERR_PROXY_*` خو **موږ پروکسي نه ده ټاکلې** | د **ویندوز** په کچه پروکسي/VPN، یا د انټي‌ویروس «ویب شیلډ» |

پروګرام اوس دا کوډونه پخپله لولي او **په پښتو** وايي چې څه شوي او کومه
پروکسي یې لامل وه — نه یوازې یوه سپینه پاڼه. همدارنګه د سیستم کچې پروکسي
هم پېژني او د «سیستم» په معلوماتو کې یې ښيي.

**د حل لاره:** د پروکسي پاڼې ته ورشئ → «وګوره» → که سوره وه، اکاونټ ته بله
پروکسي ورکړئ یا پروکسي یې بنده کړئ. که پروکسي نه وي ټاکلې خو بیا هم د
پروکسي شکایت وي، د ویندوز/انټي‌ویروس پروکسي بنده کړئ.

## هوښیار ګامونه — که یو عنصر بیا رانغی

لومړی ځل چې ګوګل ته ورشئ، د کوکیزو پیغام ښکاري او تاسو یې تایید کوئ. دوهم
ځل هغه پیغام نه راځي — پخوا به سکریپټ همدلته ناکام شو.

اوس پروګرام یو ورک عنصر داسې څېړي:

1. که تاسو پخپله ګام **«اختیاري»** په نښه کړی وي → پرېښودل کېږي
2. که د ګام تڼۍ د **منلو/بندولو** په څېر ښکاري (`Accept`, `قبول`, `منل`, …)
   → پرېښودل کېږي
3. که **راتلونکی ګام** لا اوس په پاڼه کې موجود وي (یعنې پاڼه مخکې تللې ده)
   → پرېښودل کېږي
4. که هېڅ یو هم نه وي → دا یوه ریښتینې ستونزه ده، سکریپټ درېږي او انځور اخلي

د هر ګام په څنګ کې د **!** / **؟** تڼۍ ده چې «اړین» او «اختیاري» بدلوي.

## براوزر او پروسې — څه وخت تړل کېږي؟

| څه کېږي | براوزر | د Python سرور |
|---|---|---|
| چلول بریالی شي | تړل کېږي (که «پرانیستی پرېږده» بند وي) | روان پاتې |
| چلول ناکام شي یا ودرول شي | **پرانیستی پاتې کېږي** — چې کار مو نیمګړی پاتې نشي | روان پاتې |
| ثبتولو کې تېروتنه وشي | **پرانیستی پاتې کېږي** | روان پاتې |
| یو ټب وتړل شي | ثبتول روان وي، بل ټب ته ځي | روان پاتې |
| د پروګرام کړکۍ وتړل شي | تړل کېږي | **تړل کېږي** |
| پروګرام کریش شي یا په زوره وتړل شي | تړل کېږي | **تړل کېږي** (تر ۲ ثانیو کې) |

سرور د پروګرام د پروسې شمېره (`--parent-pid`) ساتي او هرې دوې ثانیې یې ګوري.
که پروګرام نه وي، سرور پخپله وځي — نو هېڅکله به داسې پروسه پاتې نشي چې نه
کړکۍ ولري، نه یې په Task Manager کې ومومئ، او د پروګرام فولډر یې بند وساتي.

## ولې بیا چلول کار کوي که سایټ بدل شي؟

هر ګام لپاره یوازې یو پته نه، بلکې **څو لارې** ثبتېږي — له تر ټولو ټینګې تر
تر ټولو کمزورې:

```
1. data-testid=…      ← تر ټولو ښه
2. #id (که ثابت وي)
3. name=…
4. aria-label=…
5. placeholder / title
6. د متن له مخې (//button[text()="خوندي کول"])
7. د CSS لار (div > button:nth-of-type(2))
8. بشپړ XPath              ← وروستۍ هڅه
```

د چلولو پرمهال یوه یوه ازمویل کېږي، تر څو یوه ورکار شي. که یوه لار مات شي،
بله یې ځای نیسي.
