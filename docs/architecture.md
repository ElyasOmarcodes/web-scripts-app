# جوړښت (Architecture)

## لنډه کتنه

```
┌──────────────────────────┐        HTTP + WebSocket        ┌──────────────────────────┐
│  Flutter (Dart) UI       │ ─────────────────────────────► │  Python backend          │
│  frontend/lib            │ ◄───────────  پېښې  ──────────  │  FastAPI · 127.0.0.1:8765│
└──────────────────────────┘                                └────────────┬─────────────┘
                                                                         │ Selenium
                                                                         ▼
                                                            ┌──────────────────────────┐
                                                            │  Microsoft Edge          │
                                                            │  (ځانګړی پروفایل)        │
                                                            └──────────────────────────┘
```

ظاهري برنامه هېڅکله مستقیم له براوزر سره کار نه کوي؛ هر څه له API نه تېرېږي.
دا معنا لري چې کمانډ لاین (`cli.py`) او UI دواړه یو منطق کاروي.

---

## ثبتول څنګه کار کوي؟

Selenium پخپله د کارونکي کلیکونه نه اوري. نو:

1. Python د `js/recorder.js` فایل په پاڼه کې **انجیکټ** کوي
2. هغه JS د `click`، `input`، `change`، `keydown` پېښې د **capture** پړاو کې اوري
3. د هرې پېښې لپاره د عنصر لپاره **څو نښې (targets)** جوړوي او په حافظه کې ساتي
4. Python هر ~۲۵۰ms یو ځل `__WS_RECORDER__.drain()` بولي او لیست خالي کوي
5. هر ځل چې پاڼه بدله شي، JS له منځه ځي — Python یې بیا انجیکټ کوي
   (`drain()` چې `null` راستون کړي، یعنې انجیکشن ته اړتیا ده)

### iframe ملاتړ

په هر پړاو کې recorder ټول `iframe`ونه هم ګرځي (تر ۳ پوړه ژورو پورې) او د هرې
پېښې سره یې د چوکاټ لار (`frame_path: [0, 2]`) ساتي. د چلولو پرمهال player
همغې لارې ته ورګرځي.

### د پېښو ترتیب

هره پېښه د براوزر `Date.now()` مهر لري. له ټولو چوکاټونو راټولې شوې پېښې د
مهر له مخې ترتیبېږي، نو ترتیب سم پاتې کېږي.

## د نښو (locator) ټاکل

`buildTargets()` د یوه عنصر لپاره لاندې نامزدان جوړوي، بیا **یوازې هغه ساتي
چې بیرته همغه عنصر ومومي** (`querySelector(sel) === el`):

| ترتیب | ډول | مثال |
|---|---|---|
| ۱ | test id | `[data-testid="save-btn"]` |
| ۲ | ثابت id | `#login_form` |
| ۳ | name | `input[name="q"]` |
| ۴ | aria-label | `a[aria-label="Settings"]` |
| ۵ | placeholder / title / alt | `input[placeholder="لټون"]` |
| ۶ | role + متن | `//*[@role="button" and normalize-space(.)="خوندي کول"]` |
| ۷ | متن | `//button[normalize-space(.)="خوندي کول"]` |
| ۸ | ثابته class | `button.primary-action` |
| ۹ | د CSS لار | `#root > div:nth-of-type(2) > button` |
| ۱۰ | بشپړ XPath | `/html[1]/body[1]/div[1]/button[1]` |

**ناثبات idونه** ردېږي: هغه چې ۴+ شمېرې لري (`u_0_12345`)، د React/Ember/MUI
نمونې (`:r3`, `ember1234`)، یا اوږده هش‌شکل تارونه. همدا شان د CSS-in-JS
کلاسونه (`css-1x2y3z`, `x1abc239`).

## بیا چلول

`player.py` هر ګام دا ډول ترسره کوي:

1. سم چوکاټ ته ورګرځي (`frame_path`)
2. نښې یوه یوه ازمويي، تر څو یوه **ښکاره** عنصر ومومي — تر ۱۵ ثانیو پورې
3. عنصر د پاڼې منځ ته سکرول کوي
4. کړنه ترسره کوي:
   - **کلیک** — لومړی عادي کلیک؛ که پټ شوی وي (overlay)، د JS له لارې
   - **لیکل** — `Ctrl+A` بیا `Delete` بیا متن (د React ساحو لپاره اړین)
   - **لیست** — لومړی د ښکاره متن له مخې، بیا د `value` له مخې
5. د ګامونو ترمنځ همغه ځنډ ساتي چې کارونکي کاوه (تر ۳ ثانیو پورې، د چټکتیا
   په تناسب)

که یو ګام ناکام شي، عکس اخلي (`screenshots\`) او ټوله چاره درېږي — دا ډېر
خوندي دی، ځکه په ناسم ځای کلیک کول زیانمن کېدای شي.

## متغیرونه (Variables)

د پټنوم ساحه چې ثبت شي:

```json
{ "action": "type", "secret": true, "value": "{{password}}" }
```

او په سکریپټ کې:

```json
"variables": [{ "name": "password", "secret": true }]
```

ارزښت یوازې د `POST /api/scripts/{id}/run` په بدن کې راځي او په حافظه کې
پاتې کېږي — فایل ته نه لیکل کېږي. په هر متن کې `{{name}}` کارېدلی شي.

## API

| لار | کار |
|---|---|
| `GET /api/health` | د سرور حالت |
| `GET /api/scripts` | لیست |
| `POST /api/scripts` | نوی جوړول |
| `GET /api/scripts/{id}` | بشپړ سکریپټ |
| `PUT /api/scripts/{id}` | بدلول (نوم، ګامونه، متغیرونه) |
| `DELETE /api/scripts/{id}` | ړنګول |
| `POST /api/scripts/{id}/run` | چلول |
| `POST /api/record/start` | ثبتول پیل |
| `POST /api/record/stop` | ثبتول پای + خوندي کول |
| `POST /api/session/stop` | روانه چاره ودرول |
| `GET /api/session` | اوسنی حالت |
| `GET /api/events` | وروستۍ پېښې |
| `WS /ws` | ژوندی جریان |

په یوه وخت کې یوازې **یوه** چاره (ثبتول یا چلول) روانېدلی شي — که بله وغواړئ،
سرور `409` راستنوي.
