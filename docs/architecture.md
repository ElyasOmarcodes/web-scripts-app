# جوړښت (Architecture)

## لنډه کتنه

```
┌──────────────────────────┐        HTTP + WebSocket        ┌──────────────────────────┐
│  Flutter (Dart) UI       │ ─────────────────────────────► │  Python backend          │
│  frontend/lib            │ ◄───────────  پېښې  ──────────  │  FastAPI · 127.0.0.1:8765│
└──────────────────────────┘                                └────────────┬─────────────┘
                                                                         │ Selenium
                                                                         ▼
                                                            ┌──────────────────────────┐
                                                            │  Microsoft Edge          │
                                                            │  (ځانګړی پروفایل)        │
                                                            └──────────────────────────┘
```

ظاهري برنامه هېڅکله مستقیم له براوزر سره کار نه کوي؛ هر څه له API نه تېرېږي.
دا معنا لري چې کمانډ لاین (`cli.py`) او UI دواړه یو منطق کاروي.

---

## ثبتول څنګه کار کوي؟

Selenium پخپله د کارونکي کلیکونه نه اوري. نو:

1. Python د `js/recorder.js` فایل په پاڼه کې **انجیکټ** کوي
2. هغه JS د `click`، `input`، `change`، `keydown` پېښې د **capture** پړاو کې اوري
3. د هرې پېښې لپاره د عنصر لپاره **څو نښې (targets)** جوړوي او په حافظه کې ساتي
4. Python هر ~۲۵۰ms یو ځل `__WS_RECORDER__.drain()` بولي او لیست خالي کوي
5. هر ځل چې پاڼه بدله شي، JS له منځه ځي — Python یې بیا انجیکټ کوي
   (`drain()` چې `null` راستون کړي، یعنې انجیکشن ته اړتیا ده)

### iframe ملاتړ

په هر پړاو کې recorder ټول `iframe`ونه هم ګرځي (تر ۳ پوړه ژورو پورې) او د هرې
پېښې سره یې د چوکاټ لار (`frame_path: [0, 2]`) ساتي. د چلولو پرمهال player
همغې لارې ته ورګرځي.

### د پېښو ترتیب

هره پېښه د براوزر `Date.now()` مهر لري. له ټولو چوکاټونو راټولې شوې پېښې د
مهر له مخې ترتیبېږي، نو ترتیب سم پاتې کېږي.

## د نښو (locator) ټاکل

`buildTargets()` د یوه عنصر لپاره لاندې نامزدان جوړوي، بیا **یوازې هغه ساتي
چې بیرته همغه عنصر ومومي** (`querySelector(sel) === el`):

| ترتیب | ډول | مثال |
|---|---|---|
| ۱ | test id | `[data-testid="save-btn"]` |
| ۲ | ثابت id | `#login_form` |
| ۳ | name | `input[name="q"]` |
| ۴ | aria-label | `a[aria-label="Settings"]` |
| ۵ | placeholder / title / alt | `input[placeholder="لټون"]` |
| ۶ | role + متن | `//*[@role="button" and normalize-space(.)="خوندي کول"]` |
| ۷ | متن | `//button[normalize-space(.)="خوندي کول"]` |
| ۸ | ثابته class | `button.primary-action` |
| ۹ | د CSS لار | `#root > div:nth-of-type(2) > button` |
| ۱۰ | بشپړ XPath | `/html[1]/body[1]/div[1]/button[1]` |

**ناثبات idونه** ردېږي: هغه چې ۴+ شمېرې لري (`u_0_12345`)، د React/Ember/MUI
نمونې (`:r3`, `ember1234`)، یا اوږده هش‌شکل تارونه. همدا شان د CSS-in-JS
کلاسونه (`css-1x2y3z`, `x1abc239`).

## بیا چلول

`player.py` هر ګام دا ډول ترسره کوي:

1. سم چوکاټ ته ورګرځي (`frame_path`)
2. نښې یوه یوه ازمويي، تر څو یوه **ښکاره** عنصر ومومي — تر ۱۵ ثانیو پورې
3. عنصر د پاڼې منځ ته سکرول کوي
4. کړنه ترسره کوي:
   - **کلیک** — لومړی عادي کلیک؛ که پټ شوی وي (overlay)، د JS له لارې
   - **لیکل** — `Ctrl+A` بیا `Delete` بیا متن (د React ساحو لپاره اړین)
   - **لیست** — لومړی د ښکاره متن له مخې، بیا د `value` له مخې
5. د ګامونو ترمنځ همغه ځنډ ساتي چې کارونکي کاوه (تر ۳ ثانیو پورې، د چټکتیا
   په تناسب) — او تل لږ تر لږه د `human.py` تصادفي فاصله

که یو ګام ناکام شي، عکس اخلي (`screenshots\`) او ټوله چاره درېږي — دا ډېر
خوندي دی، ځکه په ناسم ځای کلیک کول زیانمن کېدای شي. یوازینی استثنا هغه ګام
دی چې عنصر یې **په حقیقت کې شتون نه لري** (لاندې «هوښیار ګامونه» وګورئ).

### د چلولو تال

ثبتول د ګامونو تر منځ دمه **نه** ساتي (`delay_ms` نور نه لیکل کېږي). د چلولو
ټول تال له `human.py` راځي، او یوازې هغه انتظار پاتې دی چې واقعاً اړین وي:
عنصر ته لټون، د پاڼې بارېدل. هغه ګام چې پرېښودل یې احتمال وي (اختیاري، یا د
منلو/بندولو تڼۍ) یوازې ۲٫۵ ثانیې لټول کېږي، نه ټول `step_timeout`.

### انساني چلند (`human.py`)

یو `Human` څیز د هرې چارې لپاره تصادفي، خو منطقي شمېرې جوړوي:

| څه | ارزښت |
|---|---|
| د ګامونو تر منځ فاصله | `uniform(0.5, 1.5)` ثانیې — او هېڅکله د ثبت شوي ځنډ نه کمه |
| د «فکر کولو» وقفه | ~۱۶٪ وخت، اضافي ۱٫۸–۳٫۶ ثانیې |
| د کلیک ټکی | د ویجټ د منځني ۶۰٪ ساحې دننه تصادفي ټکی (`ActionChains` + offset) |
| لیکل | حرف په حرف، ۴۵–۱۶۰ms، کله ناکله یوه اوږده وقفه |
| سکرول | ~۲۲٪ وخت، ۸۰–۳۲۰px (کله پورته، کله ښکته) |

سربېره پر دې، `driver.py` د هرې پاڼې له پیل نه مخکې یو کوچنی JS ورکوي چې
`navigator.webdriver` او د اتوماتیک کولو نورې نښې پټوي.

### هوښیار ګامونه (که عنصر ورک وي)

د کوکیزو پیغام یوازې لومړی ځل ښکاري. کله چې یو عنصر ونه موندل شي، `_should_skip`
پرېکړه کوي:

```
step.optional == True                       → پرېږده
که کړنه click/hover/scroll/press_key نه وي  → ناکامي
د تڼۍ متن د منلو/بندولو په څېر وي           → پرېږده
راتلونکی ګام لا اوس په پاڼه کې موجود دی     → پرېږده
نور                                          → ناکامي (+ عکس)
```

پرېښودل شوی ګام د `step_skipped` پېښه خپروي او په پایله کې `skipped` شمېرل
کېږي؛ `smart_skip` په تنظیماتو کې بندېدای شي.

## اکاونټونه او کوکیز

یو اکاونټ دوه شیان لري:

| | څه دي | ولې |
|---|---|---|
| **پروفایل** | `accounts/profiles/<id>/` | دا هغه څه دي چې ناسته ژوندۍ ساتي — دقیقاً لکه بېل براوزر |
| **کوکیز** | `accounts/cookies/<id>.json` | د لېږدولو وړ کاپي؛ یوه تازه پروفایل ته یې ورکوو او پرې پوهېږو چې ناسته لا سمه ده |

### ننوتل

```
POST /api/accounts/login/start {category}
   └─ کوچنۍ کړکۍ (560×780) د هغه اکاونټ په پروفایل کې پرانیستل کېږي
   └─ هر ثانیه: driver.get_cookies() → د سایټ کوکیز فلټر شي
   └─ که د ناستې کوکي (c_user / auth_token / sessionid / SID …) ولیدل شوه:
        ۲.۵ ثانیې انتظار (چې پاتې کوکیز هم ولیکل شي) → خوندي کول → کړکۍ تړل
POST /api/accounts/login/finish   ← لاسي بدیل، که پېژندنه پاتې راشي
```

پټنوم هېڅکله له براوزر څخه نه وځي — پروګرام یې نه ویني.

### د چلولو پر مهال

```
POST /api/scripts/{id}/run    {account_id}
POST /api/record/start        {account_id}   ← ثبتول هم همدا لار کاروي
   └─ براوزر د هغه اکاونټ په پروفایل کې پیلېږي
   └─ apply_cookies(): هر دومېن پرانیستل کېږي → add_cookie() → بیا تازه کول
   └─ بیا د سکریپټ لومړی ګام (یا د ثبتولو پیل پته)
```

`add_cookie()` یوازې ځینې ساحې مني، نو نور (`priority`, `sourceScheme` …)
لرې کېږي. **`domain` خو ساتل کېږي**: که یې لرې کړو، `.facebook.com` بدلېږي په
یوه host-only کوکي چې یوازې `facebook.com` یې ویني — `www.facebook.com` یې نه
ویني، نو سایټ بیا د ننوتلو پاڼه ښیي. که براوزر دومېن ونه مني، بیا پرته له
دومېن هڅه کېږي.

### حدونه

هره کټګوري خپل `max_accounts` لري (فیسبوک ۲، ایکس ۳، انسټاګرام ۱ …) چې په
`accounts.json` کې خوندي کېږي. **نیمګړي** اکاونټونه (هغه چې ننوتل یې بشپړ
نه شول) حد کې نه شمېرل کېږي، نو یوه پاتې راغلې هڅه بله نه بندوي.

## د پروسو ژوند (`lifetime.py`)

د Flutter پروګرام او د Python سرور دوې جلا پروسې دي. که سرور پاتې شي، هېڅ
کړکۍ نه لري چې کارونکی یې ووینی — او خپل `.exe` بند ساتي، نو فولډر نه ړنګېږي.

دوه ساتونکي یې مخه نیسي:

```
--parent-pid <د پروګرام PID>   ← هرې ۲ ثانیې کتل کېږي؛ پروګرام لاړ = سرور وځي
هېڅ UI ونښلېد تر ۹۰ ثانیو      ← او هېڅ چاره روانه نه وي = سرور وځي
POST /api/shutdown             ← د کړکۍ د تړلو پر مهال پروګرام یې وهي
```

دواړه یوه لاره کاروي: `SessionManager.shutdown()` براوزر تړي، بیا پروسه وځي.
که سرور بیا هم ځواب ورنکړي، پروګرام یې د `taskkill /T /F` په مرسته وژني.

## کارونه (`tasks.py`)

یو کار = یو سکریپټ + یو لیست اکاونټونه + د چلولو تنظیمات. هر اکاونټ خپله
`AccountRun` لري (`pending` / `running` / `ok` / `failed` / `stopped`)، او د
کار رنګ له همدې راځي:

```
ټول ok                       → done    (شین)
ټول failed                   → failed  (سور)
ځینې ok، ځینې failed         → partial (ژیړ)
څه پاتې (pending/stopped)    → partial (ژیړ)
```

### همزمانه چلول

```
lanes = min(task.concurrency, د اکاونټونو شمېر)
هر lane یو جلا Thread دی چې له یوې ګډې کتار څخه اکاونټ اخلي
هر lane خپل براوزر لري (د اکاونټ خپل پروفایل) — نو ناستې سره نه ګډېږي
driver.tile(lane, lanes) پرېکړه کوي چې کړکۍ د پردې کوم ځای ونیسي
```

د پردې وېش: ۱ = ټوله پرده، ۲ = ښي/کیڼ، ۳–۴ = څلور برخې.

### د کمپیوټر د وس اندازه (`machine.py`)

```
cores_needed = 0.25 + کړکۍ × 0.55 × (پټ وي؟ 0.65 : 1)
ram_needed   = 220MB + کړکۍ × 380MB × (پټ وي؟ 0.80 : 1)
load         = cores_needed ÷ د کمپیوټر هستې
```

`psutil` ریښتینې هستې، ټوله او ازاده حافظه لولي؛ که نه وي، یوازې هستې
(`os.cpu_count`) پاتې کېږي او راپور کې `measured: false` ښکاري. د چلولو پر
مهال `LoadSampler` هرې ثانیې نمونه اخلي، نو په پای کې د کار په لاګ کې ریښتینې
اعظمي اندازه لیکل کېږي — اټکل او واقعیت دواړه یو ځای.

### د کار خپل لاګ

هر کار خپل `task-logs/<id>.jsonl` لري: هر کرښه یوه پېښه (`ts`, `level`,
`message`, `account_id`, `lane`). فایل چې له ۵۰۰KB واوړي، وروستۍ ۶۰۰ کرښې
ساتل کېږي.

### دوام ورکول

`task.pending_accounts()` هغه اکاونټونه راګرځوي چې `ok` نه دي. «دوام ورکړه»
یوازې هغوی چلوي، او د بشپړو شویو پایلې نه لمسوي.

## د کوکیزو ژوندیتوب (`login.check_cookies`)

```
کوکي نشته                        → dead
د ناستې ټول کوکیز نېټه تېره ده   → dead   (پرته له براوزره)
کوکیز پلي شول + سایټ ناسته وپېژندله → alive
سایټ ناسته ونه پېژندله            → dead
براوزر پیل نه شو / انټرنیټ نشته  → unknown
```

وروستۍ کرښه مهمه ده: هغه څه چې پېژندل یې ونه شول، **سور نه ګڼل کېږي**. یو غلط
سور کارونکی بې ځایه بیا ننوتلو ته اړ باسي.

## متغیرونه (Variables)

د پټنوم ساحه چې ثبت شي:

```json
{ "action": "type", "secret": true, "value": "{{password}}" }
```

او په سکریپټ کې:

```json
"variables": [{ "name": "password", "secret": true }]
```

ارزښت یوازې د `POST /api/scripts/{id}/run` په بدن کې راځي او په حافظه کې
پاتې کېږي — فایل ته نه لیکل کېږي. په هر متن کې `{{name}}` کارېدلی شي.

## API

| لار | کار |
|---|---|
| `GET /api/health` | د سرور حالت |
| `GET /api/scripts` | لیست |
| `POST /api/scripts` | نوی جوړول |
| `GET /api/scripts/{id}` | بشپړ سکریپټ |
| `PUT /api/scripts/{id}` | بدلول (نوم، ګامونه، متغیرونه) |
| `DELETE /api/scripts/{id}` | ړنګول |
| `POST /api/scripts/{id}/run` | چلول (`account_id` اختیاري) |
| `GET /api/accounts` | کټګورۍ + اکاونټونه |
| `POST /api/accounts/login/start` | د ننوتلو کړکۍ پرانیستل |
| `POST /api/accounts/login/finish` | کوکیز نیول او خوندي کول |
| `PATCH /api/accounts/{id}` | نوم بدلول |
| `DELETE /api/accounts/{id}` | ړنګول (کوکیز + پروفایل هم) |
| `PATCH /api/accounts/categories/{id}` | حد اکثر بدلول |
| `POST /api/record/start` | ثبتول پیل |

| `GET /api/session` | اوسنی حالت |

| `WS /ws` | ژوندی جریان |

په یوه وخت کې یوازې **یوه** چاره (ثبتول یا چلول) روانېدلی شي — که بله وغواړئ،
